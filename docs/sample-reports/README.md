# Sample Reports — Reporting Module

This folder contains real CSV exports generated by the QueueSmart Reporting
Module, produced against the running backend and its live SQLite database
(not hand-written or mocked).

## Files

- `user-participation-report-example.csv` — one row per registered user, summarizing their queue participation history.
- `service-activity-report-example.csv` — one row per service, combining service details with its queue activity.
- `queue-usage-stats-example.csv` — a single-row summary of overall queue usage statistics.

## How the reports were generated

1. Logged in as an Administrator via `POST /api/auth/login` to obtain a bearer token.
2. Called `GET /api/reports/export?type=<users|services|stats>` with that token.
3. The server (`server/modules/reporting/reporting.service.js`) queried the
   `history`, `services`, `queues`, and `queue_entries` tables, computed the
   report rows, and serialized them to CSV with the `csv-stringify` library.
4. The response was returned with `Content-Type: text/csv` and a
   `Content-Disposition: attachment` header, then saved to disk here.

The same export is available from the admin UI: **Reports** screen →
optional date-range / service filters → **Generate Report** → **Export CSV**
on any of the three report cards. The button triggers the same
`/api/reports/export` endpoint and downloads the file through the browser.

All three endpoints (and their JSON equivalents at `/api/reports/users`,
`/api/reports/services`, `/api/reports/stats`) also accept optional
`startDate`, `endDate`, and `serviceId` query filters to scope the report to
a date range and/or a single service.

## What data each report includes

- **User participation** — user id, email, full name, role, total visits,
  served/left-queue/no-show counts, and last visit date.
- **Service activity** — service id, name, description, duration, priority,
  current queue status and length, and historical served/left/no-show counts
  plus average wait time.
- **Queue usage stats** — total queue entries, users served, users who left
  the queue, no-shows, average wait time in minutes, and how many users are
  currently waiting.

## Who can access it

Administrator accounts only. Every reporting endpoint (`/api/reports/*`) is
gated behind `requireAuth` + `requireAdmin` middleware — an unauthenticated
request gets `401`, and an authenticated non-admin (regular customer)
account gets `403`. In the frontend, the Reports screen only exists inside
the admin app shell (`src/App.jsx`), which customer accounts never route
into.
